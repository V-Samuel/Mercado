1\. Visão Geral da Arquitetura de Interface



O frontend do sistema é dividido em três aplicações independentes, mas conectadas à mesma API REST (Laravel):



Landing Page: Site público otimizado para SEO e conversão, apresentando o produto.



Painel Web (React): Sistema de gestão (Dashboard, PDV, Relatórios) acessado via navegador.



App Mobile (React Native): Ferramenta de bolso para leitura de código de barras e contagem de estoque.



2\. Padrões Visuais e Stack Tecnológica



Para garantir alta performance e evitar overhead (peso desnecessário) no sistema de gestão, o projeto adotará uma separação estrita de dependências entre o site de vendas e as ferramentas operacionais.



Landing Page (Marketing):



Utilizará React ou Next.js.



Bibliotecas de Animação (Exclusivas desta camada): Framer Motion para microinterações e GSAP para efeitos de rolagem. Estas bibliotecas não farão parte do repositório/build do painel administrativo.



Painel Web Operacional (Gestão):



React (Vite) + Tailwind CSS.



Foco absoluto em performance, tempo de resposta e interações instantâneas. Zero uso de bibliotecas de animação complexas. As únicas transições serão as nativas do CSS (ex: mudança rápida de cor ao passar o mouse em um botão).



App Mobile (Operação):



React Native (Expo). Foco no acesso rápido à câmera e renderização instantânea das listas de produtos.



Comunicação: Axios para requisições HTTP, utilizando interceptadores para injetar o token JWT (Sanctum) nas rotas privadas.



3\. Estrutura da Landing Page Pública



Focada em conversão (AIDA), utilizando animações para guiar o olhar do usuário sem comprometer a performance.



|Seção|Objetivo / Conteúdo|Comportamento Animado (Framer Motion / GSAP)|
|-|-|-|
|Hero (Topo)|Capturar atenção imediata com a proposta de valor e mockup do sistema.|Entrada suave (fade-in / slide-up) nos textos e destaque pulsante no botão de "Criar Conta".|
|Features|Explicar o leitor de código de barras, alertas de estoque e painel financeiro.|Cards de funcionalidades surgem em cascata (stagger) à medida que o usuário rola a página.|
|Prova Social|Gerar desejo através de métricas (ex: "Controle seu estoque em 2 minutos").|Contadores numéricos dinâmicos que disparam do zero até o valor final ao entrarem na tela.|
|Call to Action|Converter o visitante em usuário ou direcionar para o WhatsApp.|Botão primário com microinteração de escala ao passar o mouse.|



4\. Arquitetura do Aplicativo Mobile (Apoio Operacional)

Focado exclusivamente na agilidade física dentro da loja (prateleiras e depósito).



HomeScreen: Interface com botões massivos e coloridos ("Entrada", "Saída", "Consultar").



ScannerScreen: Aciona a câmera do dispositivo nativamente para ler códigos de barras (EAN/UPC) nos produtos.



ActionScreen: Após a leitura, exibe o nome do produto lido e um teclado numérico grande para inserir a quantidade da movimentação.



5\. Gerenciamento de Estado e Requisitos Não Funcionais

Performance de Renderização (Painel e App): Como o sistema será usado no dia a dia do comércio, as interfaces de gestão e PDV devem responder aos cliques e inserções de dados imediatamente. O bundle (tamanho final do código) do painel web será mantido o menor possível através da exclusão deliberada de dependências de animação.



Performance Visual (Landing Page): O site público fará uso de Lazy Loading (carregamento sob demanda) para que as animações do GSAP e Framer Motion não penalizem a nota de SEO e o tempo de carregamento inicial no Google Lighthouse.
