1\. Visão Geral do Projeto 



Nome do Sistema: (AEMEK)



Objetivo: Desenvolver uma plataforma eficiente para que pequenos comerciantes possam registrar produtos, monitorar entradas e saídas e receber alertas de estoque baixo.



2\. Arquitetura e Tecnologias



Para manter o sistema escalável e facilitar a manutenção, uma arquitetura baseada em API REST é o ideal.



Backend / API: PHP utilizando o framework Laravel. Facilita a criação de rotas, autenticação e regras de negócio com o Eloquent ORM.



Banco de Dados: MySQL. Estrutura relacional perfeita para garantir a integridade das transações financeiras e de estoque.



Frontend (Painel Administrativo): JavaScript/React. Interface responsiva para o lojista acessar via computador.



Mobile (Apoio Operacional): React Native. Um aplicativo complementar focado em tarefas de balcão ou depósito, como usar a câmera do celular para leitura de código de barras e contagem rápida de estoque.



3\. Modelo de Dados (DER Essencial)



O banco de dados precisa ser enxuto, mas capaz de gerar um histórico rastreável.



|Tabela|Campos Principais|Relacionamentos|
|-|-|-|
|usuarios|id, nome, email, senha, nivel\_acesso|-|
|categorias|id, nome, descricao|1:N com produtos|
|produtos|id, nome, sku/codigo\_barras, preco\_custo, preco\_venda, estoque\_atual, estoque\_minimo, categoria\_id|N:1 com categorias <br />1:N com movimentacoes|
|movimentacoes|id, produto\_id, tipo (entrada/saida), quantidade, data, usuario\_id, motivo (venda, ajuste, quebra)|N:1 com produtos<br />N:1 com usuarios|



O campo nivel\_acesso pode aceitar apenas dois valores:



admin: Acesso irrestrito (cadastra usuários, vê dashboard financeiro, vê preço de custo).



operador: Acesso focado na operação (faz vendas, dá baixa no estoque, consulta o catálogo, mas não apaga produtos nem vê relatórios financeiros).



4\. Casos de Uso Principais (Requisitos Funcionais)



Gestão de Inventário (CRUD de Produtos): O usuário deve poder cadastrar, editar, inativar e listar produtos.



Registro de Movimentações: Toda alteração de estoque (venda ou reposição) deve gravar um registro na tabela de movimentações para auditoria, e então atualizar o estoque\_atual do produto.



Alertas de Reposição: O painel inicial (Dashboard) deve exibir uma lista de produtos onde o estoque\_atual é menor ou igual ao estoque\_minimo.



Relatório de Fluxo: Geração de um extrato simples mostrando as entradas e saídas de um período específico.



5\. Requisitos Não Funcionais



Performance: Consultas ao estoque devem ser indexadas para respostas em menos de 500ms, evitando filas no balcão do lojista.



Usabilidade: A interface deve seguir princípios de Flat Design, com botões grandes e fluxos de no máximo 3 cliques para realizar uma venda ou dar baixa em um produto.



Segurança: Senhas com hash (bcrypt nativo do Laravel) e autenticação de rotas via JWT (JSON Web Tokens) ou Laravel Sanctum.
